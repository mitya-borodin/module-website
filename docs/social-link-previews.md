# Превью ссылок Ritmod в мессенджерах и соцсетях

Дата реализации и проверки: **9 октября 2026 года**. Владелец требования —
[публичный web-контракт](../../module-market-intelligence/internet-promotion/spec/public-web-contract.md#превью-ссылок-ritmod-уточнение-9-октября-2026).

## Проблема и результат

Автор показал ссылку с названием и маленькой иконкой без изображения. Проверка `https://ritmod.ru/`
перед изменениями: HTTP 200, в исходном HTML нет Open Graph и Twitter Card; есть
`noindex,nofollow`. Это подтверждённый недостаток разметки, а не доказательство конкретного
состояния кеша мессенджера.

Главная и ПО теперь содержат в исходном HTML `og:title`, `og:description`, `og:type`,
`og:site_name`, `og:locale`, `og:url`, свойства изображения и `twitter:card=summary_large_image`.
Для документации сохранён стандартный Head Starlight с метаданными каждой страницы и добавлено
изображение соответствующей автоматизации. Клиентский JavaScript не нужен. Canonical и изображения
имеют абсолютные HTTPS-адреса `ritmod.ru`, без localhost и параметров исходной ссылки.

Главная показывает щит; ПО — обзор систем дома. Широкие JPEG 1200×630 сохраняют исходный кадр
целиком с полями. Документация использует свои изометрические обложки в исходной пропорции,
шириной 1200px; обзор и резервная картинка — прежняя изометрическая сцена целого дома.
Изображения страниц и тексты описаний автоматизаций не изменялись. Индексация, домен, серверные
настройки, deployment и производственная логика автоматизаций не входят в изменение.

## Владельцы реализации

- [site-layout.astro](../src/layouts/site-layout.astro): метаданные и выбор обложки главной/ПО.
- [social-image-meta.astro](../src/components/social-image-meta.astro): JPEG через Astro,
  абсолютный адрес, MIME, размеры и alt для Open Graph и Twitter Card.
- [docs-head.astro](../src/components/docs-head.astro): расширение стандартного Starlight Head;
  десять тематических обложек и резервная обзорная. Подключение — [astro.config.mjs](../astro.config.mjs).
- [home-v1.jpg](../src/assets/social/home-v1.jpg) и [software-v1.jpg](../src/assets/social/software-v1.jpg):
  широкие версии одобренных исходников `service-cabinet-wiren-board-v4.png` и `software-home-interior-v1.png`.

Широкие версии подготовлены штатным установленным Sharp: `resize(1200, 630, { fit: 'contain',
background: '#f0eee6' }).jpeg({ quality: 90, mozjpeg: true })`. При замене исходников обновлять
эти два файла. В сборке Astro создаёт JPEG с хешем содержимого и качеством 85; адрес меняется
при изменении изображения. Новых зависимостей и клиентских скриптов нет.

## Проверка и граница публикации

- `yarn build`: успешен, `astro check` — 0 errors, 0 warnings, 0 hints.
- Проверены все 14 HTML-страниц без meta-redirect: обязательные поля присутствуют,
  социальные поля не дублируются, `og:url` совпадает с canonical, OG/Twitter указывают один JPEG.
- Фактические размеры JPEG совпадают с метаданными. 13 разных изображений; максимальный размер
  151 276 байт. HTML каждой страницы меньше 1 MB.
- Локальная production-сборка `http://127.0.0.1:4322`: изображения возвращают 200 и `image/jpeg`.
  Главная и ПО отдают одинаковые метаданные обычному браузеру, Twitterbot и facebookexternalhit.
  Проверка HTTP выполнена для всех 14 страниц, включая штатную страницу 404.
- Широкие картинки просмотрены: щит и сцена ПО целиком, без обрезки. Layout страниц не менялся,
  новая browser-проверка адаптивности для этого изменения не требовалась.

**Статус: реализовано и проверено локально, не опубликовано этим проходом.** После публикации
проверить прямые HTTPS-адреса из `og:image` и новую отправку ссылки в целевом мессенджере.
Нельзя считать локальную проверку доказательством обновления ранее отправленных сообщений.
Окончательное оформление карточки и срок обновления её кеша определяет сервис.

## Источники, проверены 9 октября

- [Open Graph protocol](https://ogp.me/): базовые поля и свойства изображения.
- [Apple TN3156: Create rich previews for Messages](https://developer.apple.com/documentation/technotes/tn3156-create-rich-previews-for-messages):
  `og:title` и `og:image` для крупных превью, метаданные в исходном HTML без JavaScript,
  одинаковый ответ разным User-Agent и рекомендация изображения от 900px по ширине.
