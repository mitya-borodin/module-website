# Совместимость мобильного CSS

Статус: исправление сборки подготовлено локально **09.10.2026**, публикация не выполнялась.
Владелец: этот документ; область — совместимость CSS media queries коммерческих страниц.

## Дефект и evidence

Автор прислал два снимка iPhone: в составе комплекта и этапах работы остались четыре колонки,
текст накладывается, в шапке показано настольное меню. Версия iOS/Safari на устройстве неизвестна.

09.10.2026 прочитаны HTML `https://ritmod.ru/` и подключённый файл
`/_astro/commercial-content.Cj4lwWtX.css`. Viewport корректный: `width=device-width, initial-scale=1`.
В опубликованном CSS мобильные правила имеют вид `@media (width<=650px)` и
`@media (width<=1100px)`, хотя в исходниках записаны через `max-width`.
Такие же преобразования обнаружены в локальной production-сборке до исправления.

Поддержка range-синтаксиса media queries появилась в
[Safari 16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/).
В более старом Safari эти условия не применяются, что объясняет оба дефекта и настольное меню.
Связь с конкретной версией телефона — вывод по симптомам, а не проведённая проверка этого устройства.

## Решение

В [astro.config.mjs](../astro.config.mjs) задан `vite.build.cssTarget: 'safari15'`.
Минификатор сохраняет совместимые `min-width`/`max-width`, вместо перевода в range-синтаксис.
[Контракт Vite](https://vite.dev/config/build-options#build-csstarget) подтверждён также по
локальному `node_modules/vite/dist/node/chunks/node.js`: CSS-minify передаёт `build.cssTarget`
в Lightning CSS. Это не отключение минификации и не новый dependency.

Сами сетки сохраняют исходную адаптацию: до 650px одна колонка, до 1100px две, выше четыре.
До 1100px показывается мобильное меню. JS target, логика автоматизаций и контент не менялись.
Этот target не является обещанием полной поддержки всех возможностей сайта в Safari 15:
он не полифиллит JS, container queries и другие отсутствующие API.

## Проверка и повторяемый контроль

- `yarn build` — успешно, `astro check`: 0 errors, 0 warnings.
- Проверены CSS-файлы и inline `<style>` собранных HTML: 33 источника, 66 media queries,
  range-синтаксиса нет; в общем CSS присутствуют `(max-width:650px)` и `(max-width:1100px)`.
- Браузер, главная: 320×740, 375×812 и 430×932 — одна колонка обоих блоков и мобильное меню;
  768×1024 — две колонки; 1280×800 — четыре колонки и настольная навигация.
  Горизонтального переполнения нет. На 375px меню открывается и закрывается, ширина 315px.
- По дополнительному снимку автора проверен блок контактов: прежняя опубликованная сетка
  также зависела от несовместимого media query. В исправленном CSS `.contact-grid` находится
  внутри `(max-width:850px)`. Браузер 320×740 и 375×812: одна колонка, памятка ниже контактов,
  одинаковая ширина блоков, обрезанного текста и горизонтального переполнения нет.

  Отдельная production-правка не потребовалась: этот случай закрывает общий CSS target.

После изменения Astro/Vite/CSS-minifier проверять именно production CSS, включая inline-стили:
адаптивные media queries должны сохранять `min-width`/`max-width`, без сравнений `<` и `>`.
Dev-режим и современный браузер не выявляют несовместимость синтаксиса со старым Safari.
Это ручной build-artifact check, отдельного автоматического script/gate пока нет.

На физическом iPhone из обращения исправление ещё не проверено. После публикации новой сборки
нужно открыть главную и проверить оба блока и мобильное меню на этом устройстве.
